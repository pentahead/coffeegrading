## DATA_FLOW (TARGET SETELAH ML ADA)
1) SampleInput → Room sample_info → navigasi ke Camera dengan sampleInfoId.
2) CameraViewModel memuat batchName + coffeeType dari Room (sudah ada).
3) User capture / galeri → Bitmap (sudah ada di CameraScreen).
4) [BARU] Engine ML: Bitmap → Result / Either dengan List<Detection> (lihat kontrak).
5) [BARU] Grading: List<Detection> + coffeeType → defectScore, gradeText,
   daftar agregasi per jenis cacat untuk scan_defect.
6) ScanViewModel menyimpan via ScanRepository.saveScanResult(...) seperti
   sebelumnya (lihat ScanHistoryEntity, ScanDefectEntity).
7) onSaveAndShowDetail(historyId) — tidak diubah.

## SUGGESTED_PUBLIC_API (IMPLEMENTASI AI — SESUAIKAN NAMA DENGAN MODEL ANDA)
Minimal yang harus terpenuhi secara perilaku (bukan nama mutlak):

  (A) suspend fun runInference(bitmap: Bitmap): Result<List<DetectionDto>>
      DetectionDto minimal: classIndex: Int, score: Float
      Opsional sesuai model: bbox, mask coefficients, dsb.

  (B) fun aggregateDefects(detections: List<DetectionDto>): AggregatedDefects
      Output: totalScore: Double, rows untuk scan_defect (nama tampilan,
      count, defectValue per baris), totalBeansCount (definisikan eksplisit).

  (C) fun gradeFromScore(totalScore: Double, coffeeType: String?): String
      Output: "Mutu 1" .. "Mutu 6" / "Mutu 4a" / "Mutu 4b" / "Mutu 4" / di luar
      standar — harus konsisten dengan GradeColors (lihat util/GradeColors.kt).

  (D) ScanViewModel: tambahkan kembali metode persistensi yang menerima hasil
      (A)(B)(C) + path gambar + duration ms + sampleInfoId; hindari duplikasi
      logika simpan Room di CameraScreen.

## ERROR_HANDLING_CHECKLIST
- Gagal load model → Result.failure; UI: Toast (pattern sudah ada di project).
- Bitmap null / width==0 → jangan inferensi.
- Shape tensor tidak sesuai → log error + kembalikan empty / failure (jangan
  hasil diam-diam salah).
- OOM → tangkap; kurangi resolusi input atau batasi max side di preprocessing.
